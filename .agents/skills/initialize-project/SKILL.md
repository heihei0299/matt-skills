# Initialize Project

显式调用本 skill，在目标项目根目录初始化或刷新项目上下文。先读取事实，再写文件；不凭目录名、包名或猜测补全项目目标。

## 1. 收集事实

读取能说明项目真实行为的版本化材料：

- `README.md`、现有 `AGENTS.md`、`PROJECT.md`、`CONTEXT.md` 和相关文档
- `package.json`、其他 manifest、构建/运行配置
- 根目录和主要源码目录，定位架构边界、入口、关键职责
- 测试目录、测试配置和 CI 配置，确认测试规则与稳定命令

优先记录稳定且代理需要知道、但不能从一次查找直接得出的事实。不要把完整命令清单、依赖清单、动态路线图或重复的通用规则写进 `PROJECT.md`。若项目用途、范围、入口或六项内容无法从仓库确认，一次性向用户询问缺失事实后再写入。

文档语言跟随目标仓库的主要语言；没有明确语言信号时跟随用户语言。保留现有文档的其他内容。

## 2. 更新 `AGENTS.md`

维护唯一的受管区块，使用以下标记：

```md
<!-- matt-skills:managed:start -->
## 项目上下文
### 架构边界
见 `PROJECT.md` 的“架构边界”。
### 仓库地图
见 `PROJECT.md` 的“仓库地图”。
### 标准命令
见 `PROJECT.md` 的“标准命令”。
### 测试规则
见 `PROJECT.md` 的“测试规则”。
### 项目约束
见 `PROJECT.md` 的“项目约束”。
### 完成标准
见 `PROJECT.md` 的“完成标准”。
<!-- matt-skills:managed:end -->
```

- 六个 `###` 标题必须按 `架构边界`、`仓库地图`、`标准命令`、`测试规则`、`项目约束`、`完成标准` 顺序出现。
- 受管区块总行数必须不超过 30 行；只写简要规则或 `PROJECT.md` 指针，详细事实只放 `PROJECT.md`。
- 已有完整标记区块时原位替换；没有时追加到文件末尾；不得重排、覆盖或改写其他内容。
- `AGENTS.md` 不存在时，优先复制目标项目的 `template/AGENTS.md`，再追加区块；模板不可用时创建最小 `AGENTS.md`，只包含该区块。
- 无论项目是否存在 `CLAUDE.md`，初始化状态和项目上下文都固定维护在 `AGENTS.md`。

## 3. 更新 `PROJECT.md`

维护 `PROJECT.md` 专用受管标记（不要与 `AGENTS.md` 的 CLI 受管标记混用）：

```md
<!-- initialize-project:start -->
## 项目概览
### 项目用途
### 项目范围
### 主要入口
### 架构边界
### 仓库地图
### 标准命令
### 测试规则
### 项目约束
### 完成标准
<!-- initialize-project:end -->
```

将每个标题填成基于仓库事实的详细说明：

- **项目用途**：解决的问题、服务对象和预期结果。
- **项目范围**：负责的能力，以及仓库明确排除的范围；没有证据就不臆造非目标。
- **主要入口**：用户入口、应用/包入口和代理应先看的文档或目录。
- **架构边界**：模块职责、依赖方向、外部系统边界和不可跨越的层次边界。
- **仓库地图**：关键目录及其职责；只列影响代理决策的稳定目录。
- **标准命令**：少量最常用且稳定的开发、验证或发布入口；命令的完整来源仍以 manifest 和配置为准。
- **测试规则**：测试位置、测试层级、命名/运行约定，以及失败时必须保留的证据。
- **项目约束**：运行时、兼容性、安全、生成文件、依赖或发布方面的明确约束。
- **完成标准**：实现、验证、文档、工作区或提交范围方面的交付要求。

`PROJECT.md` 不存在时创建标题 `# Project Context` 后写入区块。已存在且含完整标记时只替换标记内内容；已存在但没有标记时在末尾追加区块，不覆盖自由格式内容。若标记不成对，停止写入并报告，避免破坏文档。不得生成空章节、`TBD` 或未经确认的事实。

## 4. 完成检查

写入后确认：

- `AGENTS.md` 区块只有一份，六个标题顺序正确且总行数不超过 30 行。
- `PROJECT.md` 区块只有一份，九个章节均有事实内容，且其他内容未改变。
- 第二次运行会原位替换而不是追加重复内容。
- 只修改目标 `AGENTS.md`/`PROJECT.md` 和本 skill 需要的文件；不创建备份或额外模板资源。
